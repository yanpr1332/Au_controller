## 一、本轮开发并通过验收的功能

### A. 原生多轨 Track Arm / Visibility

`controller_modules/native_qa_batch.py` 的 `native_track_state_roundtrip_qa`：

- 限制于 `tests/native_outputs/ACCEPT_AU_*.sesx` 受控会话；
- Audition 原生 `AudioTrack.armed` 执行 `false → true → false`；
- Audition 原生 `AudioTrack.visible` 执行 `true → false → true`；
- 每一步在原生对象上读回，保存 QA 会话，不调用录音功能；
- 收尾必须确认只涉及 `tests/` 下的 QA 文档，随后通过第二轮 JSX 请求完成独立关闭和 `DOCUMENTS=0` 验证。

**实机发现及修复：** 保存以后，当前脚本中旧 `doc.closeDocument()` 对象有时抛出 `Unknown error exception`；但随后通过新的隔离请求、反向枚举 DocumentCollection 并关闭，可以成功清除测试会话。该修复只针对 QA 文档，不会遍历关闭用户自己的文档。

轨道 armed 的成功不等于麦克风、ASIO 输入或录音文件完成验收。

### B. 原生批量导入与批量处理

`native_batch_open_qa`：连续打开、回读并关闭 **3 个 WAV**，源 SHA256 不变。

`controller_modules/native_batch_processing.py`：

- 受控、逐项执行真实 Audition `WaveDocument.applyFavorite` / `saveAsDocument`；
- Favorite：3 份 WAV，调用 `Normalize to -3 dB`，返回真值，检查已结束、不繁忙并回读输出；另经真实音频测量：三份输出峰值均约 **-3.01 dBFS**（原始峰值分别约 -16.12、-26.02、-21.94 dBFS），证据 `tests/receipts/phase09_favorite_audio_measurement.json`；
- 重采样：3 份 WAV 转 **32 kHz / 16-bit PCM**，由 SciPy 解码检验数据类型、帧数和输出哈希；
- 单文件 48 kHz → 44.1 kHz / 24-bit 的额外实机验证也已通过；
- 输出前进行路径白名单、重复输入、防覆盖检查；支持干运行、文件级错误回报以及遇错停止。

这证明了 QA 范围的原生 Favorite 和 SampleTypeConversion API 路线；不等于 Au 全部原生 Batch Process 对话框功能可被无条件远程控制。

### C. 原生 Marker 类型与保存往返

`controller_modules/native_marker_kinds.py`：

- Cue 点标记（duration=0）创建成功；
- Cue 范围标记（duration>0）创建成功；
- Subclip 类型创建成功；
- `CD Track` 作为本机类型字符串被原生接口拒绝，因此**没有**列为支持类型；
- 保存 WAV、重新用 Audition 打开以后，可回读到 **3 个标记**；源 WAV 哈希保持不变。

### D. 批量音频响度与 MP3 交付

`controller_modules/batch_mastering.py`：声明式、多文件、双遍 FFmpeg Loudnorm，目标响度和真峰值限定；每份文件独立暂存，独占发布校验 SHA256，输入只读；失败可以隔离或停止。

本轮的真实输出：
- **2 个**音频完成 -18 LUFS 目标批量母带，双遍结果满足代码的响度/真峰值验收容差；
- **1 个**故意缺失的源文件被隔离，其他音频正常交付；
- **2 个**实际 MP3 文件经 WSL FFmpeg 输出并完成校验。

这些是可靠的**离线**能力，不计作 Audition 原生 Match Loudness 交付。
