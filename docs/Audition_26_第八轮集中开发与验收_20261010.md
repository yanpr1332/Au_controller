## 2. Au ExtendScript 执行可靠性

对 Controller 的 `_run_jsx` 通信流程实施：

1. 时间戳纳秒值 + 随机 nonce 区分任务；相同任务名连续执行不发生临时文件冲突。
2. 对执行超时进行有限范围验证，统一使用 `time.monotonic()`。
3. 收到 `ERROR=...` 时，向 Python 调用者抛出明确异常，避免错误被当成成功。
4. 在成功、失败和超时后，仅清理该任务的 JSX 和回应临时文件。
5. 不擅自杀死 Adobe Audition 宿主进程，也不关闭用户工程。

12 项专项测试验证了伪宿主故障注入、超时、重复调用、非法参数、批处理隔离、碰撞保护。
另外，经真实 Audition 26.0.0 原生宿主 `status()` 回读，以及主动抛出隔离的 JSX 异常验证了实际错误回传。

重要边界：**故障注入的超时测试为模拟执行器，不证明超时能够中断正在运行的 Audition 脚本**；
本轮把 AU012 与 AU258 标记为 `verified_offline`，不冒充 `verified_native_live`。
AU263 完整操作错误报告仍需扩展结构化错误码和恢复语义。

## 3. 批量音频交付

新增 `controller_modules/batch_delivery.py`，公开 `batch_transcode_audio`：

- 无确认时只提供规划；限制单次 1–100 个源文件。
- 支持 WAV、FLAC、MP3 等 FFmpeg 既有目标格式；采样率、声道和码率受白名单限制。
- 源文件名和目标路径冲突预检、Windows 下不区分大小写重复输出检查。
- 每项转换独立暂存；实际发布使用排他创建防覆盖，完成后进行 SHA256 校验。
- 每个输入返回独立状态；损坏或缺失文件不会影响后续合法媒体，另提供遇错停止模式。
- 保留源文件 SHA256，确认源文件未被改写；即使转换失败也尽可能清理本项暂存。
- 严格标识 `native_audition_export: false`，没有声称是 Audition 自带 Batch Process。

实机验收：
- 输出 **2 份 FLAC、1 份 MP3**，全部经 FFprobe 回读为 **48 kHz 双声道**，SHA256 匹配；
- 插入 1 个缺失源文件，实际批处理中独立失败 1 项，成功 2 项；
- 原文件哈希保持不变，批处理临时目录无残留。

- Audition CEP 宿主 PlugPlugSetup 仍未证明加载成功；当前不开放 WebSocket/evalScript 面板承诺。
- 原生 `AudioBusTrackCollection.remove` 仍为失效接口；可用 SESX 安全回避不等于修复 SDK。
- 频谱修复、Essential Sound/诊断 UI、原生效果架与深度 Automation、ASIO 录音、5.1、Premiere/AAF/OMF，以及 AMIO C++ SDK / Control Surface 缺少单独原生验收。
- 本轮并未把外部 FFmpeg 批量输出用于关闭 Audition 原生 Favorites/Batch 能力的验收缺口。
