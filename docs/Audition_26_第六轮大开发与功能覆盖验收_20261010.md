## 2. 本轮实际完成

### 2.1 Native Audition 多轨复制、编排与混音

Controller：arrange_native_qa_clips，位于 controller_modules/native_arrangement.py。
只在 ACCEPT_AU_ 测试 SESX 的空白已有音轨复制合成测试剪辑，生成唯一 clip ID；支持采样点开始位置和不高于 1 的线性 Clip 增益。
拒绝失效/Offline 媒体、目标非空音轨、重复目标、危险增益与覆盖原始文件。

实际测试把合成母源分布在四条音轨上，Audition 重新打开后四条音轨各有一个剪辑。
Audition 原生 Mixdown 成功导出 48 kHz / float32 / 199200 frames WAV，峰值约 -14.36 dBFS。
原始 SESX 未变化，新的 Native Mixdown 位于：
tests/native_outputs/phase06_native_arrangement_mix.wav。

实证：tests/receipts/phase06_native_arrangement_acceptance.json 和 phase06_arrangement_closed.json。

这是基于真实 SESX 结构的受控复制，并非“SDK 支持任意导入外部文件到任意轨道”。

### 2.2 17 组实际 FFmpeg 效果链与 29 种可验证的滤镜配方

Controller：
- effects_recipe_validate
- render_audio_effects
- batch_effect_recipes

模块：controller_modules/effect_recipes.py。

类型化参数白名单，限制每组滤镜个数、数值上下限、输出格式，禁止任意 shell/filter 字符串透传和覆盖源文件。

两个真实验收批次：
- 第一批 9 组：人声高通、降噪、DeEsser、压缩；Hum/Notch；DeClick/DeClip；Delay/Chorus；EQ、Band Filter；Pitch/Tempo；Trim/Fade；Gate/Dynaudnorm；Flanger。
- 第二批 8 组：Amplify/Limit、BandPass、Reverse、Mono、Silence Trim、NLM Denoise、LowPass、Echo。

17 份真实文件均通过 FFprobe、时长/声道/采样峰值和哈希回读，其中静音裁剪把约 4 秒人声 WAV 调整为 2.02 秒，单声道转换实际输出声道数 1。

实证：tests/receipts/phase06_effects_batch.json、phase06_effects_second_batch.json。
**不是 Audition 自带效果器参数全量开放。**

### 2.3 R128 分段响度与实际交付门禁

Controller：r128_loudness_timeline、loudness_delivery_gate、export_r128_timeline。
模块：controller_modules/r128_timeline.py。

调用 Debian FFmpeg ebur128，获取约每 100ms 的 Momentary、Short-term、累计 Integrated LUFS/LRA，并结合真实 FFmpeg loudnorm 测量进行完整性回读。
实机输出样本 4 秒、40 点；播客 -16 LUFS 交付门禁通过。

实证：tests/receipts/phase06_r128_timeline.json。

### 2.4 BWF / ID3 实际元数据交付

Controller：tag_delivery_audio。
模块：controller_modules/metadata_delivery.py。

WAV/BEXT 及 MP3/ID3v2.3 两种容器实际写入，FFprobe 核查 title、artist、description / comment、genre 等字段；音频流使用 copy，源 SHA256 不变，不覆盖已有文件。

实证：tests/receipts/phase06_tag_delivery.json。

### 2.5 Audition 原生 XMP Cue Marker 编辑和 Transport

新增：patch_native_xmp_markers；native_transport_snapshot；native_qa_transport_accept。
模块：controller_modules/xmp_marker_edit.py、native_transport_qa.py。

XMP 标记通过 SESX 原生嵌入 XMP 编辑，新建、重命名、移动、删除，经过 Audition 打开后再次读取；3 个目标标记分别位于 52,000、95,000、107,000 samples。
原生 Transport 在 QA 会话中 Play/Pause/Stop、Seek 14,000 samples、Loop 置位/清除均回读成功；测试结束恢复循环状态、播放头位置、停止状态。

实证：tests/receipts/phase06_native_xmp_edit_acceptance.json、phase06_native_transport_acceptance.json。

### 2.6 JSON 驱动的一键生产流水线及 CLI

模块：controller_modules/production_jobs.py。
Controller：production_job_plan、run_production_jobs。
CLI 新增 production、arrange-session、audit-session、effects 四类命令。

Pipeline 允许配置最多 12 个源媒体别名、24 个有向前序依赖的步骤。已支持：
- effects：参数白名单效果器串联；
- master：真实两遍响度母带；
- transcode：指定采样率、声道、码率；
- metadata：BWF/ID3 标签；
- duck：语音自动降低背景音乐；
- qc：播客/广播/音乐 WAV 质量门禁；
- r128：分段响度时间轴 JSON；
- session_audit：Native SESX 结构健康预检。

只有在所有步骤完成、所有原始输入哈希不变时才发布输出；单文件硬链接原子发布且在异常时回滚本次输出。不覆盖原文件/同名历史文件。
需说明：这是运行期异常回滚，不保证操作系统断电、进程被杀时仍具备数据库级事务语义。

实际完成完整 10 步 QA：
修复音频 → -16 LUFS 母带 → BWF 标签 → QC → R128 → MP3 转码 → ID3 标签 → Ducking → 再次母带 → QC。
实际生成 10 份媒体/JSON 文件，audition_production_receipt.json 逐步保存哈希，输入未变化。
配置示例在 examples/production_voiceover_example.json。

实证：tests/receipts/phase06_production_bundle_acceptance.json 和
tests/native_outputs/phase06_production_bundle/audition_production_receipt.json。
